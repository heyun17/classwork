# Shop 상품 목록 기능명세서

## 1. 목적

MySQL에 저장된 상품을 조회하고 상품명으로 검색하는 웹 기능의 동작, 입력 검증, 오류 응답을 정의한다.

## 2. 범위

- 상품 목록 조회
- 상품명 검색
- 상품 상세 조회 API
- 빈 검색 결과 표시
- DB 연결 실패 처리

회원, 주문, 결제, 상품 등록·수정·삭제는 현재 범위에 포함하지 않는다.

## 3. 데이터 모델

| 필드 | 타입 | 규칙 |
|---|---|---|
| `id` | integer | 1 이상인 상품 식별자 |
| `name` | string | 1~200자 |
| `price` | integer | 0 이상, 원 단위 |

## 4. 화면 기능

### 상품 목록 (`GET /`)

- 기본 진입 시 상품을 ID 오름차순으로 표시한다.
- 쿼리 파라미터 `q`가 있으면 상품명에 검색어가 포함된 상품만 표시한다.
- 검색어 앞뒤 공백을 제거하고 연속 공백을 하나로 정규화한다.
- 결과가 없으면 `검색 결과가 없습니다.`를 표시한다.
- 화면 상단에 현재 결과 수를 표시한다.

### 목록 파라미터

| 파라미터 | 기본값 | 허용 범위 |
|---|---:|---|
| `q` | 빈 문자열 | 최대 100자 |
| `offset` | 0 | 0~10,000 |
| `limit` | 100 | 1~100 |

범위를 벗어나면 FastAPI 검증 오류 `422 Unprocessable Entity`를 반환한다.

## 5. 상세 조회 API

### `GET /product/{product_id}`

- 성공: `200 OK`, 상품 JSON 반환
- 존재하지 않는 상품: `404 Not Found`
- `product_id`가 1 미만: `422 Unprocessable Entity`
- DB 오류: `503 Service Unavailable`

응답 예시:

```json
{
  "id": 1,
  "name": "노트북",
  "price": 1200000
}
```

## 6. 오류 및 보안 처리

- DB 접속 정보는 환경 변수로만 읽는다.
- DB 드라이버가 없거나 연결에 실패하면 내부 예외를 데이터 접근 오류로 변환한다.
- 검색어는 SQL 파라미터 바인딩으로 전달하며 SQL 문자열에 직접 삽입하지 않는다.
- 상품 데이터는 Pydantic 모델로 검증한다.
- 목록 조회는 최대 100건으로 제한한다.

## 7. 모듈 책임

- `config.py`: 환경 변수 읽기와 설정값 검증
- `domain.py`: 상품 모델과 도메인 검증
- `repositories.py`: SQL과 데이터 저장소 접근
- `services.py`: 검색어 정규화와 상품 업무 규칙
- `routes.py`: HTTP 파라미터 검증, 응답, 오류 상태 코드
- `main.py`: 애플리케이션 조립과 의존성 주입
- `scripts_db_check.py`: 일회성 DB 진단

## 8. 완료 기준

- `python -m unittest discover -s . -p "test_product_service.py"`가 통과한다.
- 환경 변수만 변경해 다른 MySQL 환경에 연결할 수 있다.
- DB 없이 서비스 검색 로직을 단위 테스트할 수 있다.
- 목록·상세 조회의 정상, 검증 오류, DB 오류 동작이 위 명세와 일치한다.
