01 기본문법 노트북에서 배운 코드를 여행 정보 데이터에 그대로 적용해 봅니다. 새 문법은 없습니다. 모든 예제는 코드와 결과, 설명을 함께 실었습니다.

이 자료에서 하는 RAG

RAG는 "자료를 프롬프트에 넣고 그 자료로 답하게 하기"입니다. 원래는 질문에 맞는 자료를 찾는 단계가 앞에 있지만, 여기서는 찾지 않고 문서 번호로 직접 골라서 넣습니다. 랭체인 문법에만 집중하기 위해서입니다.

데이터: travel_docs.csv

가상의 지역 '은하군'의 여행 정보 22건입니다. 장소·회사 이름이 모두 가상이라 모델은 미리 알 수 없습니다. 그래서 답이 맞으면 넣어 준 자료 덕분입니다.

준비 코드 (맨 처음 한 번)

아래 준비 코드를 한 번 실행하면, 이후 예제는 각 예제 코드만 복사해서 바로 실행할 수 있습니다. 예제마다 필요한 프롬프트와 체인을 생략 없이 모두 넣었습니다.

from dotenv import load_dotenv
load_dotenv()

import pandas as pd
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
parser = StrOutputParser()

docs = pd.read_csv("travel_docs.csv")      # doc_id, category, source, title, body
print(docs.shape)

# 문서 번호 하나로 자료 가져오기
def get_doc(doc_id: str) -> str:
    r = docs[docs["doc_id"] == doc_id].iloc[0]
    return f"[{r['doc_id']}] {r['title']}\n{r['body']}"

# 문서 번호 여러 개를 한 번에
def get_docs(doc_ids: list) -> str:
    return "\n\n".join(get_doc(i) for i in doc_ids)

print(get_doc("T02"))
(22, 5)
[T02] 별빛전망대
별빛전망대는 솔바람섬 북쪽 언덕 꼭대기에 있는 천문 관측 명소이다. 맑은 날 밤에는 은하수를 맨눈으로 볼 수 있다. 별빛전망대는 매주 월요일에 휴관하며 입장료는 5천 원이다. 전망대까지는 섬 선착장에서 걸어서 약 30분이 걸린다. 겨울철에는 오후 9시에 문을 닫는다.
설명
  • get_doc("T02")는 문서 하나를 "[번호] 제목 + 본문" 글자로 돌려줍니다. 이 글자를 프롬프트의 {context} 자리에 넣게 됩니다.
  • 모델 답(실행 결과)은 실행할 때마다 문장이 조금씩 다를 수 있습니다. 핵심 내용(요일, 가격, 비율)이 같으면 됩니다.

1기본 체인: 자료를 넣으면 달라진다

1-1. 자료 없이 물어보기

노트북 Step1의 prompt | llm | parser를 그대로 씁니다. 자료는 넣지 않습니다.

prompt = ChatPromptTemplate.from_template("당신은 은하군 여행 안내원입니다. {question}에 답해주세요.")
chain = prompt | llm | parser

print(chain.invoke({"question": "별빛전망대는 언제 쉬어?"}))
죄송하지만 은하군 별빛전망대의 휴무일에 대한 정확한 정보는 가지고 있지 않습니다.
방문 전에 공식 홈페이지나 전화로 확인해 보시기 바랍니다.
설명
  • 모델은 가상의 '별빛전망대'를 모릅니다. 그래서 모른다고 하거나, 그럴듯한 말을 지어냅니다.
  • 모델이 학습하지 않은 정보는 프롬프트에 넣어 줘야 합니다. 이것이 RAG를 하는 이유입니다.

1-2. 자료를 넣어서 물어보기

프롬프트에 빈칸 {context}를 하나 더 만들고, 거기에 T02 문서를 넣습니다.

prompt = ChatPromptTemplate.from_template(
    "아래 [자료]에 있는 내용만으로 답하세요.\n\n[자료]\n{context}\n\n[질문]\n{question}"
)
rag_chain = prompt | llm | parser

print(rag_chain.invoke({"context": get_doc("T02"), "question": "별빛전망대는 언제 쉬어?"}))
별빛전망대는 매주 월요일에 휴관합니다.
설명
  • 1-1과 바뀐 것은 {context} 빈칸 하나뿐입니다. 그런데 답이 정확해졌습니다.
  • invoke에 넣는 dict의 key(context, question)는 프롬프트의 빈칸 이름과 같아야 합니다.

1-3. 자료에 없는 걸 물으면 '없다'고 답하게 하기

자료에 없는 질문(맛집)을 하면 모델이 지어낼 수 있습니다. 규칙 한 문장을 추가해 막습니다.

prompt = ChatPromptTemplate.from_template(
    "아래 [자료]에 있는 내용만으로 답하세요. [자료]에 없으면 '자료에 없습니다'라고 답하세요.\n\n"
    "[자료]\n{context}\n\n[질문]\n{question}"
)
rag_chain = prompt | llm | parser

print(rag_chain.invoke({"context": get_doc("T02"), "question": "별빛전망대 근처 맛집 알려줘"}))
자료에 없습니다.
설명
  • 여행 안내에서 틀린 정보(없는 식당, 틀린 휴무일)는 실제 피해로 이어집니다. 모르면 모른다고 하게 만드는 규칙이 꼭 필요합니다.

1-4. 여러 질문 한 번에(batch), 글자 흐르게(stream)

노트북 ⑤ 실행에서 본 세 가지 실행 방법 중 batch와 stream을 써 봅니다.

prompt = ChatPromptTemplate.from_template(
    "아래 [자료]에 있는 내용만으로 답하세요. [자료]에 없으면 '자료에 없습니다'라고 답하세요.\n\n"
    "[자료]\n{context}\n\n[질문]\n{question}"
)
rag_chain = prompt | llm | parser

# batch: 입력 여러 개를 리스트로 한 번에
inputs = [
    {"context": get_doc("T09"), "question": "갈매기식당은 언제 쉬어?"},
    {"context": get_doc("T11"), "question": "솔바람페리는 하루 몇 번 다녀?"},
    {"context": get_doc("T13"), "question": "반딧불 트레킹 가이드는 누구야?"},
]
for r in rag_chain.batch(inputs):
    print(r)

# stream: 답을 조금씩 받아서 바로 출력
for chunk in rag_chain.stream({"context": get_doc("T15"),
                               "question": "취소하면 환불을 얼마나 받아? 자세히 설명해줘"}):
    print(chunk, end="", flush=True)
갈매기식당은 매주 화요일에 쉽니다.
솔바람페리는 하루 4회 운항합니다.
청연계곡 반딧불 트레킹의 담당 가이드는 윤솔입니다.

바람길여행 상품의 환불 규정은 다음과 같습니다.
- 출발 10일 전까지 취소: 전액 환불
- 출발 5~9일 전 취소: 80% 환불
- 출발 2~4일 전 취소: 30% 환불
- 출발 1일 전부터: 환불 불가

단, 숙소 비용은 해당 숙소 운영사의 취소 규정을 따릅니다.
환불은 결제 수단으로 영업일 기준 5일 안에 처리되며, 단체 예약은 별도 계약 조건을 따릅니다.
설명
  • batch는 결과도 입력 순서대로 리스트로 돌려줍니다.
  • stream은 긴 답을 기다리지 않고 글자가 나오는 대로 보여 줄 때 씁니다. 챗봇 화면에서 많이 씁니다.

2프롬프트 템플릿

2-1. 규칙은 system, 자료와 질문은 human

1-3의 프롬프트를 노트북 Text-to-SQL처럼 from_messages로 나눕니다. 이후 예제는 모두 이 프롬프트를 씁니다.

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
rag_chain = prompt | llm | parser

# 모델에 무엇이 전달되는지 확인 (모델은 부르지 않음)
pv = prompt.invoke({"context": get_doc("T02"), "question": "별빛전망대는 언제 쉬어?"})
for m in pv.to_messages():
    print(type(m).__name__, ":", m.content[:40])

print(rag_chain.invoke({"context": get_doc("T02"), "question": "별빛전망대는 언제 쉬어?"}))
SystemMessage : 당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세
HumanMessage : [자료]
[T02] 별빛전망대
별빛전망대는 솔바람섬 북쪽 언덕 꼭대기에
별빛전망대는 매주 월요일에 휴관합니다.
설명
  • system에는 바뀌지 않는 규칙을, human에는 매번 바뀌는 자료와 질문을 넣습니다.
  • 모델은 system 메시지를 '지켜야 할 지시'로 더 무겁게 받아들입니다. 규칙이 길어질수록 나눠 두는 것이 좋습니다.
  • prompt.invoke()만 하면 모델을 부르지 않고, 모델에 갈 메시지를 미리 볼 수 있습니다.

2-2. {role} 빈칸으로 말투 바꾸기

노트북의 "당신은 {role} 전문가입니다"처럼, 역할을 빈칸으로 만들어 말투만 바꿔 봅니다.

role_prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 {role}입니다. 아래 [자료]에 있는 내용만으로 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
role_chain = role_prompt | llm | parser

for role in ["친절한 여행 상담원", "10살 아이에게 설명하는 안내원"]:
    print(f"【{role}】")
    print(role_chain.invoke({"role": role, "context": get_doc("T12"), "question": "이 상품 소개해줘"}), "\n")
【친절한 여행 상담원】
'솔바람섬 별빛 2박3일'은 바람길여행의 투어 상품으로, 1인 39만 원(VAT 포함, 유류할증료 별도)입니다.
파도소리 리조트에서 2박하며, 별빛전망대 야간 관측과 은빛해변 산책 일정이 있습니다.
솔바람페리 왕복 승선권이 포함되고, 담당 가이드는 한별입니다. 최소 출발 인원은 6명입니다.

【10살 아이에게 설명하는 안내원】
솔바람섬에 가서 2박 3일 동안 별을 보는 여행이에요! 파도소리 리조트에서 자고,
밤에는 별빛전망대에서 은하수를 볼 수 있어요. 가격은 한 사람에 39만 원이에요.
배(솔바람페리)도 타고, 한별 가이드 선생님이 함께해요. 6명 이상 모여야 출발해요.
설명
  • 빈칸은 자료나 질문만 넣는 곳이 아닙니다. 역할·말투처럼 프롬프트의 어떤 부분이든 빈칸으로 만들 수 있습니다.
  • 말투는 바뀌었지만 가격(39만 원)과 숙소(파도소리 리조트)는 그대로입니다. 사실은 자료가 정합니다.

2-3. 답의 모양을 정해 주기

노트북 Text-to-SQL의 [Output Format]처럼, system에 답변 형식을 적어 두면 답이 항상 같은 모양으로 나옵니다.

form_prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요.\n"
               "반드시 아래 형식으로만 답하세요.\n"
               "답: (한두 문장)\n"
               "주의: (예약·휴무 등 주의할 점. 없으면 '없음')"),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
tests = [
    {"context": get_doc("T07"), "question": "계곡쉼 펜션에 강아지 데려가도 돼?"},
    {"context": get_doc("T04"), "question": "반딧불 축제 야간 탐방 그냥 가면 돼?"},
    {"context": get_doc("T10"), "question": "숲속부엌 대표 메뉴가 뭐야?"},
]
for r in (form_prompt | llm | parser).batch(tests):
    print(r, "\n")
답: 네, 계곡쉼 펜션은 반려동물 동반 투숙이 가능합니다.
주의: 주말에는 예약이 빨리 마감됩니다.

답: 아니요, 축제 기간의 야간 탐방은 사전 예약제로 운영됩니다.
주의: 탐방 중에는 손전등과 휴대폰 불빛 사용이 금지됩니다.

답: 숲속부엌의 대표 메뉴는 산채비빔밥입니다.
주의: 단체 손님은 하루 전에 예약해야 합니다.
설명
  • 형식을 정해 두면 화면에 보여 주거나 코드로 나눠 쓰기 쉽습니다.
  • 형식을 더 엄격하게 지키게 하려면 JSON 파서를 씁니다(3-2).

2-4. 프롬프트에 JSON 예시를 넣을 때는 중괄호 두 번

프롬프트 안의 { }는 빈칸으로 읽힙니다. JSON 예시를 넣으면 빈칸으로 잘못 잡힙니다.

# 잘못된 예: 중괄호 한 번
wrong = ChatPromptTemplate.from_template(
    '형식: {"answer": "답", "found": true 또는 false}\n[자료]\n{context}\n[질문]\n{question}'
)
print(wrong.input_variables)

# 올바른 예: 중괄호 두 번
right = ChatPromptTemplate.from_template(
    '형식: {{"answer": "답", "found": true 또는 false}}\n[자료]\n{context}\n[질문]\n{question}'
)
print(right.input_variables)
['"answer"', 'context', 'question']
['context', 'question']
설명
  • input_variables는 프롬프트의 빈칸 목록입니다. 잘못된 예는 "answer"까지 빈칸으로 잡았습니다.
  • 이대로 invoke하면 KeyError: missing variables {'"answer"'}가 납니다. 만들 때는 에러가 안 나고 실행할 때 나서 찾기 어렵습니다.
  • {{ }}로 쓰면 빈칸이 아니라 글자 { }로 모델에 전달됩니다. 노트북 응급/경미 판정 프롬프트도 이렇게 썼습니다.

3출력 파서

3-1. 파서가 있을 때와 없을 때

같은 체인을 파서 없이, 파서를 붙여서 실행하고 결과의 type을 비교합니다. (프롬프트는 2-1의 prompt)

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
rag_chain = prompt | llm | parser

data = {"context": get_doc("T15"), "question": "출발 3일 전에 취소하면?"}

msg = (prompt | llm).invoke(data)            # 파서 없음
print(type(msg).__name__, "|", msg.content)

text = (prompt | llm | parser).invoke(data)  # StrOutputParser
print(type(text).__name__, "|", text)
AIMessage | 출발 3일 전에 취소하면 30%를 환불받을 수 있습니다.
str | 출발 3일 전에 취소하면 30%를 환불받을 수 있습니다.
설명
  • 파서가 없으면 결과는 AIMessage 객체이고, 글자는 .content 안에 있습니다.
  • StrOutputParser는 그 .content를 꺼내 문자열로 줍니다. 그래서 바로 print하거나 다음 체인에 넘길 수 있습니다.

3-2. JSON 파서로 상품 정보 뽑아 표 만들기

상품 문서 3개(T12, T13, T14)에서 이름·가격·가이드를 뽑아 pandas 표로 만듭니다.

from langchain_core.output_parsers import JsonOutputParser

extract = ChatPromptTemplate.from_template(
    "다음 상품 자료에서 정보를 뽑아 JSON으로만 답해. 다른 설명은 넣지 마.\n"

    "[자료]\n{context}"
)
extract_chain = extract | llm | JsonOutputParser()

rows = extract_chain.batch([{"context": get_doc(i)} for i in ["T12", "T13", "T14"]])
print(type(rows[0]))

table = pd.DataFrame(rows)
print(table)

# 표에서 바로 찾기: 가이드가 한별인 상품
print(table[table["guide"] == "한별"]["name"].tolist())

  • JSON 예시의 중괄호는 2-4처럼 {{ }}로 씁니다.

3-3. 리스트 파서로 키워드 뽑기

문서마다 핵심 키워드 5개를 파이썬 리스트로 받습니다.

from langchain_core.output_parsers import CommaSeparatedListOutputParser

ids = ["T01", "T02", "T03", "T04", "T05"]

  • CommaSeparatedListOutputParser는 "a, b, c" 글자를 쉼표로 잘라 리스트 ['a', 'b', 'c']로 바꿉니다.

3-4. 판정하고 분기하기 (노트북 응급/경미 코드 변형)

먼저 "자료로 답할 수 있는지"를 JSON으로 판정하고, 그 결과로 if 분기합니다. 노트북의 level == "응급"이 found == True로 바뀐 것뿐입니다.

from langchain_core.output_parsers import JsonOutputParser

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
rag_chain = prompt | llm | parser

judge = ChatPromptTemplate.from_template(
    "아래 [자료]로 [질문]에 답할 수 있는지 판정해 JSON으로만 답해. 다른 설명은 넣지 마.\n"
    '형식: {{"found": true 또는 false, "reason": "판단 이유 한 문장"}}\n\n'
    "[자료]\n{context}\n\n[질문]\n{question}"
)
judge_chain = judge | llm | JsonOutputParser()

tests = [("T09", "갈매기식당 쉬는 날이 언제야?"),
         ("T09", "갈매기식당에 주차장 있어?")]

for doc_id, q in tests:
    data = {"context": get_doc(doc_id), "question": q}
    verdict = judge_chain.invoke(data)
    print("【질문】", q)
    print("【판정】", verdict)
    if verdict["found"] == True:
        print("【답변】", rag_chain.invoke(data))
    else:
        print("【답변】 자료에 없는 내용입니다.")
    print()
【질문】 갈매기식당 쉬는 날이 언제야?
【판정】 {'found': True, 'reason': '자료에 매주 화요일에 쉰다고 나와 있다.'}
【답변】 갈매기식당은 매주 화요일에 쉽니다.

【질문】 갈매기식당에 주차장 있어?
【판정】 {'found': False, 'reason': '자료에 주차장에 대한 정보가 없다.'}
【답변】 자료에 없는 내용입니다.
설명
  • JSON 파서를 쓰는 가장 큰 이유가 이것입니다. 결과가 dict라서 verdict["found"]로 꺼내 if문에 쓸 수 있습니다.
  • 문장으로 받으면("네, 답할 수 있어요") 코드가 판단하기 어렵습니다.
  • true/false는 JSON 파서를 거치면 파이썬의 True/False가 됩니다.
파서 고르는 법 사람이 읽으면 StrOutputParser · 표로 만들거나 if로 분기하면 JsonOutputParser · 목록으로 쓰면 CommaSeparatedListOutputParser

4순차 체인

4-1. 규정 문서 → 쉬운 설명 → 3줄 요약 → 영어

노트북 Step2의 'for문으로 줄이기' 코드에서 templates와 첫 입력만 바꿨습니다.

templates = [
    "다음 여행사 규정을 여행객이 이해하기 쉽게 풀어서 설명해줘. 숫자는 그대로 써줘:\n{text}",
    "다음 내용을 딱 3줄로 요약해줘. 환불 비율은 빠뜨리지 마:\n{text}",
    "다음 한국어를 외국인 여행객용 영어로 번역해줘:\n{text}",
]

result = get_doc("T15")                       # 첫 입력: 환불 규정 문서
for i, template in enumerate(templates, start=1):
    chain = ChatPromptTemplate.from_template(template) | llm | parser
    result = chain.invoke({"text": result})   # 앞 단계 결과가 다음 단계 입력
    print(f"【{i}단계】\n{result}\n")
【1단계】
바람길여행 상품을 취소할 때 환불 금액은 언제 취소하느냐에 따라 달라요.
출발 10일 전까지 취소하면 전액, 5~9일 전이면 80%, 2~4일 전이면 30%를 돌려받고,
출발 1일 전부터는 환불이 안 됩니다. 숙소 비용은 숙소 운영사의 규정을 따릅니다.
환불은 결제한 수단으로 영업일 기준 5일 안에 들어오고, 단체 예약은 따로 정한 조건을 따릅니다.

【2단계】
1. 출발 10일 전까지 취소하면 전액 환불됩니다.
2. 5~9일 전 취소는 80%, 2~4일 전 취소는 30% 환불되며, 1일 전부터는 환불되지 않습니다.
3. 숙소 비용은 숙소 운영사의 취소 규정을 따릅니다.

【3단계】
1. Cancel at least 10 days before departure for a full refund.
2. Cancellations 5–9 days before receive an 80% refund, 2–4 days before a 30% refund; no refund from 1 day before.
3. Accommodation costs follow the cancellation policy of the accommodation operator.
설명
  • result 변수 하나를 계속 덮어쓰면서 다음 단계로 넘깁니다. 단계가 늘어도 templates에 문장만 추가하면 됩니다.
  • 단계를 거칠수록 숫자가 빠지거나 바뀌기 쉽습니다. 그래서 프롬프트에 "숫자는 그대로", "환불 비율은 빠뜨리지 마"를 넣었습니다.

5RunnableLambda

5-1. 문서 번호만 넣으면 답하는 체인

지금까지는 get_doc()을 체인 밖에서 불렀습니다. 노트북 마스킹 체인처럼 이 일을 RunnableLambda로 체인 안에 넣습니다.

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
rag_chain = prompt | llm | parser

from langchain_core.runnables import RunnableLambda

# 입력 {"doc_ids": [...], "question": "..."}  →  프롬프트용 {"context": ..., "question": ...}
def to_prompt_input(x):
    return {"context": get_docs(x["doc_ids"]), "question": x["question"]}

doc_chain = RunnableLambda(to_prompt_input) | prompt | llm | parser

print(doc_chain.invoke({
    "doc_ids": ["T12", "T15", "T16"],
    "question": "솔바람섬 별빛 2박3일을 출발 5일 전에 취소하면 환불은 어떻게 돼?"
}))
출발 5일 전에 취소하면 바람길여행 상품 비용은 80% 환불됩니다.
다만 숙소(파도소리 리조트) 비용은 해온호스피탈리티 규정에 따라 체크인 3~6일 전 취소에 해당하여 50% 환불됩니다.
설명
  • 노트북: RunnableLambda(mask_privacy) | (lambda x: {"text": x}) | prompt | llm | parser → 여기: RunnableLambda(to_prompt_input) | prompt | llm | parser. 맨 앞 '입력 바꾸기' 단계만 다릅니다.
  • 이 질문은 상품(T12: 숙소가 파도소리 리조트), 여행사 규정(T15: 5일 전 80%, 숙소는 따로), 숙소 규정(T16: 3~6일 전 50%) 세 문서가 모두 있어야 맞게 답할 수 있습니다.
  • 실제 RAG에서는 이 to_prompt_input 자리에서 질문에 맞는 문서를 자동으로 찾습니다(검색). 뒤의 prompt | llm | parser는 그대로입니다.

5-2. 이름이 비슷한 자료가 섞여 있을 때

'바람길여행'과 '바람결여행', '파도소리 리조트'와 '솔바람호텔'처럼 헷갈리는 자료를 함께 넣어 봅니다. 규칙 한 줄로 틀리지 않게 합니다.

from langchain_core.runnables import RunnableLambda

def to_prompt_input(x):
    return {"context": get_docs(x["doc_ids"]), "question": x["question"]}

strict_prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요. "
               "질문에 나온 이름과 정확히 같은 이름의 자료만 근거로 쓰세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
strict_chain = RunnableLambda(to_prompt_input) | strict_prompt | llm | parser

tests = [
    {"doc_ids": ["T15", "T22"], "question": "바람길여행 상품을 출발 3일 전에 취소하면 환불은?"},
    {"doc_ids": ["T06", "T20"], "question": "파도소리 리조트 운영사는?"},
]
for r in strict_chain.batch(tests):
    print(r)
바람길여행 상품을 출발 3일 전에 취소하면 30%를 환불받습니다.
파도소리 리조트의 운영사는 해온호스피탈리티입니다.
설명
  • T22(바람결여행)에는 "3일 전까지 취소하면 전액 환불"이 있습니다. 이 자료와 섞이면 바람길여행도 전액 환불이라고 잘못 답할 수 있습니다.
  • 자료를 여러 개 넣을수록 이런 혼동이 생기기 쉽습니다. 실제 RAG에서도 검색 결과에 비슷한 문서가 섞여 들어오므로, 이런 규칙이 자주 쓰입니다.

6Gradio 화면

6-1. 문서를 골라 질문하는 화면

노트북 마스킹 + Gradio 코드를 바꿔, 문서를 고르고 질문하면 답이 나오는 화면을 만듭니다. 출력 두 칸 구조(마스킹 결과 / 안내문)는 노트북과 같습니다.

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 은하군 여행 안내원입니다. 아래 [자료]에 있는 내용만으로 답하세요. "
               "[자료]에 없으면 '자료에 없습니다'라고 답하세요."),
    ("human", "[자료]\n{context}\n\n[질문]\n{question}"),
])
rag_chain = prompt | llm | parser

import gradio as gr

choices = [f"{r.doc_id} {r.title}" for r in docs.itertuples()]   # 예: "T02 별빛전망대"

def process(choice, question):
    doc_id = choice.split()[0]          # "T02 별빛전망대" → "T02"
    context = get_doc(doc_id)
    answer = rag_chain.invoke({"context": context, "question": question})
    return context, answer

gr.Interface(
    fn=process,
    inputs=[gr.Dropdown(choices, label="문서 선택"), gr.Textbox(label="질문")],
    outputs=[gr.Textbox(lines=6, label="📄 모델에 전달된 자료"),
             gr.Textbox(lines=6, label="💬 답변")],
    title="은하군 여행 안내",
).launch()
(화면) 문서 선택: T09 갈매기식당 / 질문: 대표 메뉴가 뭐야?
📄 모델에 전달된 자료:
[T09] 갈매기식당
갈매기식당은 노을항 앞에 있는 해산물 식당으로, 주인은 박바다이다. 갈매기식당의 대표 메뉴는 전복 물회이며 매주 화요일에 쉰다. 점심시간에는 대기 줄이 길어 일찍 가는 것이 좋다. 포장 주문도 가능하다.
💬 답변: 갈매기식당의 대표 메뉴는 전복 물회입니다.
설명
  • inputs가 두 개면 process 함수도 인자 두 개를 받습니다. outputs가 두 개면 return도 두 개입니다.
  • 모델에 전달된 자료를 화면에 같이 보여 주면, 답이 어떤 자료에서 나왔는지 확인할 수 있습니다. RAG 서비스에서 '출처 보기'가 이 역할입니다.

정리
