## 1. 한 문장 요약

**EDR은 회사 PC와 서버에 깔린 'CCTV + 경비원'이고, 우리는 그 경비원의 1차 판단을 대신하는 AI 에이전트를 만든다.**

## 2. 비유로 보는 전체 그림

| 건물 경비 | 보안관제 | 이 실습에서 |
|---|---|---|
| CCTV 녹화 | **텔레메트리**: PC에서 일어난 모든 일의 기록 | 시뮬레이터가 만든 가상 기록 → OpenSearch |
| "새벽 3시 금고 앞에 사람" 같은 경보 규칙 | **탐지 룰** | 제공 코드 (룰 몇 개) |
| 경보 | **알림(alert)** | OpenSearch `edr-alerts` 인덱스 |
| 경보가 울리면 녹화를 돌려 보는 경비원 | **트리아지**: 진짜 공격인지 판단 | **LangGraph 에이전트** |
| 경비 매뉴얼 | **대응 플레이북, 사내 정책** | PDF 9종 → **RAG** |
| "건물 봉쇄는 팀장 허락 받고" | **사람 승인 (Human-in-the-loop)** | 그래프가 멈추고 승인을 기다림 |
| 근무일지 | **트리아지 리포트** | 판정, 근거, 권고, 승인 결과 |

## 3. 꼭 알아야 할 용어 10개

| 용어 | 뜻 | 예 |
|---|---|---|
| **EDR** (Endpoint Detection & Response) | PC·서버(엔드포인트)의 활동을 기록하고, 수상한 행동을 탐지하고, 대응하는 보안 제품 | |
| **텔레메트리** | EDR이 수집하는 활동 기록 | "09:12:03 WS-007에서 cmd.exe가 rundll32.exe를 실행함" |
| **프로세스 트리** | 어떤 프로그램이 어떤 프로그램을 실행했는지의 족보 | explorer.exe → winword.exe → **powershell.exe** (워드가 PowerShell을? 수상하다) |
| **SOC** (Security Operations Center) | 알림을 24시간 보고 판단하는 보안관제센터 | |
| **알림 / 탐지 룰** | 규칙에 걸리면 생기는 경보 | "오피스 프로그램이 셸을 실행하면 알림" |
| **오탐 (False Positive)** | 정상인데 공격으로 잘못 울린 알림. **알림의 대부분이 오탐**이다 | IT 관리 도구가 PowerShell을 실행함 |
| **트리아지** | 알림을 보고 "진짜인가, 얼마나 급한가"를 1차로 가르는 일 | 정상 종결 / 의심(사람 검토) / 악성 |
| **MITRE ATT&CK** | 공격자의 행동을 정리한 공개 지식베이스. 기법마다 ID가 있다 | T1059.001 = PowerShell 악용 |
| **격리 (Isolation)** | 감염 의심 PC를 네트워크에서 끊는 대응. 업무가 멈추므로 **승인이 필요**하다 | |
| **HITL** (Human-in-the-loop) | AI가 위험한 결정을 하기 전에 사람이 승인하는 구조 | 에이전트가 격리를 권고 → 팀장 승인 → 실행 |

## 4. 왜 AI 에이전트인가

- 알림은 하루 수천 건이고 대부분 오탐입니다. 분석가는 매번 같은 일을 반복합니다. 프로세스 트리를 보고, 통신 기록을 보고, 매뉴얼을 찾고, 보고서를 써요.
- 이 **반복 조사를 에이전트가 1차로** 하면 분석가는 정말 애매한 건과 승인에만 집중할 수 있습니다.
- 대신 AI는 틀릴 수 있습니다. 그래서 세 가지 장치가 필요합니다.
  - **근거 추적:** 실제로 조회한 기록만 근거로 쓰게 한다.
  - **사람 승인:** 격리 같은 위험한 조치는 사람이 결정한다.
  - **품질 측정(LLMOps):** 얼마나 맞히는지, 얼마나 지어내는지, 얼마나 느리고 비싼지 숫자로 잰다.

## 5. 이 실습에서 에이전트가 하는 일 (한 장 요약)

```
알림: "WS-007에서 rundll32가 comsvcs.dll MiniDump 실행 (LSASS 덤프 의심)"
  │
  ├─ ① 조사 (도구 호출: 🔍 기록 담당의 조사 도구)
  │     get_process_tree(WS-007, pid) → explorer → cmd → rundll32
  │     get_process_activity(...)     → C:\Windows\Temp\d.dmp 파일 생성
  │
  ├─ ② 판정 (LLM)  → 악성, 신뢰도 0.9, T1003.001, 근거 이벤트 2개
  │     └─ 가드레일: 인용한 근거가 진짜 조회한 기록인가?
  │
  ├─ ③ 대응 권고 (RAG: 📘 문서 담당의 플레이북 검색)
  │     search_playbook("LSASS 덤프 대응 승인") → "격리는 SOC 팀장 승인" (01번 정책 PDF)
  │     → 권고: 호스트 격리, 계정 비밀번호 초기화, 포렌식 수집
  │
  ├─ ④ 사람 승인 (HITL) ⏸  … 팀장이 API로 승인
  │
  └─ ⑤ 리포트 저장
```

**도구 호출(①)과 RAG(③)의 차이**가 이 실습의 핵심 개념 중 하나입니다.

| | 도구 호출 (텔레메트리) | RAG (플레이북) |
|---|---|---|
| 질문 형태 | "WS-007의 pid 1234 부모는?" (조건이 정확함) | "LSASS 덤프면 어떻게 대응해?" (의미로 찾음) |
| 검색 방식 | 필터·정렬 (term, range) | 파싱 → 청킹 → 임베딩 → 키워드+벡터 하이브리드 |
| 결과 | 기록(사실) | 문서 조각(지식·규칙) |
| 담당 | 🔍 기록 담당 | 📘 문서 담당 |



## 참고: 예시 알림 읽는 법

5장의 예시 알림을 조각별로 풀어 봅니다.

```
알림: "WS-007에서 rundll32가 comsvcs.dll MiniDump 실행 (LSASS 덤프 의심)"
```

| 조각 | 뜻 |
|---|---|
| **WS-007** | 회사 PC 이름. WS는 Workstation(직원용 PC)의 약자. 실습 속 가상 회사의 7번 PC |
| **rundll32** | Windows에 **원래 들어 있는 정상 프로그램**. DLL 파일 안의 기능을 실행해 준다 |
| **comsvcs.dll** | 역시 Windows 기본 부품(DLL). 그 안에 **MiniDump** 기능이 있다 |
| **MiniDump** | 실행 중인 프로그램의 **메모리 내용을 파일로 통째로 복사**하는 기능. 원래는 프로그램이 죽었을 때 원인을 분석하는 진단용 |
| **LSASS** | Windows에서 **로그인을 처리하는 핵심 프로세스**. 로그인한 사람들의 자격증명(비밀번호 해시 등)이 이 메모리에 남아 있다 |
| **덤프 의심** | 누군가 LSASS의 메모리를 파일로 복사하려 했다는 뜻 |

### 왜 위험한가
- LSASS 메모리를 파일로 빼내면, 공격자는 **이 PC에 로그인했던 사람들의 비밀번호 정보**를 꺼낼 수 있다.
- 관리자가 한 번이라도 로그인했던 PC라면 관리자 권한까지 넘어가, **PC 한 대의 침해가 회사 전체로 번지는 계기**가 된다. 그래서 critical로 다룬다.
- 비유하면 **"경비실 열쇠함을 통째로 복사기에 올려놓은 장면"**.

### 정상 프로그램인데 왜 수상한가
- rundll32와 comsvcs.dll은 둘 다 **Windows 기본 부품**이다. 악성코드를 따로 설치하지 않고 **이미 있는 도구를 악용**하므로, "악성 파일"을 찾는 방식으로는 잡기 어렵다.
- 그래서 EDR은 **"무엇이 실행됐나"보다 "무엇을 하려 했나"(행위)**를 본다. "LSASS 메모리를 덤프한다"는 행동 자체가 일반 업무에서는 거의 없는 일이다.
- MITRE ATT&CK ID: **T1003.001** (자격증명 덤프: LSASS 메모리)

### 에이전트는 이 알림을 받으면 무엇을 확인하나
알림 한 줄만으로 판정하지 않고, 도구로 더 확인한다.

| 확인 | 도구 | 질문 |
|---|---|---|
| 누가 실행했나 | `get_process_tree` | 사용자가 연 명령창에서? 보안 벤더의 진단 도구에서? |
| 결과물이 생겼나 | `get_process_activity` | Temp 같은 임시 폴더에 `.dmp` 파일이 만들어졌나? |
| 그다음에 무슨 일이 있었나 | `get_host_timeline` | 덤프 직후 외부로 큰 전송이 있었나? |

- **오탐인 경우:** 서명된 벤더 진단 도구가 변경 관리 기록과 함께 실행했다.
- **악성인 경우:** 위 조건이 아니다 → 플레이북(02번 PDF)에 따라 **호스트 격리, 비밀번호 초기화, 포렌식 수집**을 권고하고, 격리는 **SOC 팀장 승인**을 기다린다.

### 역할 정하기 (1분)

둘 중 한 명은 **기록 담당**, 다른 한 명은 **문서 담당**을 맡습니다.

- 🔍 **기록 담당**: PC에 남은 **기록**을 살펴보는 사람
  → "이 알림이 울리기까지 PC에서 **무슨 일이 있었지?**"를 조사합니다.
- 📘 **문서 담당**: 보안팀의 **문서**를 살펴보는 사람
  → "이런 일이 생기면 **어떻게 판단하고 대응하라고** 적혀 있지?"를 조사합니다.

2장의 경비 비유로 말하면, 기록 담당은 **CCTV를 돌려 보는 사람**, 문서 담당은 **경비 매뉴얼을 펴 보는 사람**입니다.

> > 이 역할은 실습에서 **각자 맡는 영역**이 됩니다.
> - **혼자 만드는 것:** 기록 담당은 기록을 찾아 주는 **조사 도구**를, 문서 담당은 매뉴얼을 찾아 주는 **플레이북 검색(RAG)**을 만듭니다.
> - **함께 만드는 것:** 두 사람의 결과물을 연결하는 **에이전트**와, 서버에 올리는 **인프라**는 둘이 같이 만듭니다.
> - **바꿔서 해 보는 것:** 서로의 영역에 작은 작업을 하나씩 해 봅니다. 그래야 상대가 만든 것도 설명할 수 있습니다.

### 🔍 기록 담당: 이 알림이 울리기까지 PC에서 무슨 일이 있었나?

참고에서 "EDR은 프로그램 이름보다 **행동**을 본다"고 했습니다. 그 행동이 **실제로 어떤 기록으로 남는지** 찾아봅니다.

**질문 1. 프로그램이 실행될 때, EDR의 기록에는 어떤 칸들이 남을까?**
- 실행된 프로그램 이름, 실행할 때 붙인 명령, 그 프로그램을 실행한 '부모' 프로그램… 또 무엇이 있나요?
- 그중 예시 알림을 띄우는 데 **꼭 필요했던 칸**은 무엇일까요?
- 웹검색어(구글등): `Sysmon Event ID 1`, `EDR process creation event`
  - 예: Microsoft Sysmon 공식 문서의 “Event ID 1: Process creation” 부분 (https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon)

**질문 2. comsvcs.dll 말고도, 정상 프로그램이 공격에 쓰이는 예를 하나 찾아보기**
- 그 프로그램은 원래 무엇을 하는 프로그램인가요?
- 기록의 어느 칸을 보면 "이상하다"고 알아챌 수 있을까요?
- 웹검색어(구글등): `LOLBAS project`, `living off the land`
  - 예: [LOLBAS Project](https://lolbas-project.github.io/)

**문서 담당에게 알려 줄 것:** 이 알림이 진짜 공격인지 확실히 하려면 **기록을 무엇 무엇 더 찾아봐야 하는지** 두 가지와 그 이유

### 📘 문서 담당: 이런 일이 생기면 어떻게 판단하고 대응하나?

참고에서 "T1003.001", "플레이북에 따라 권고한다"고만 했습니다. 그 **지식과 절차가 실제로 어떻게 생겼는지** 찾아봅니다.

**질문 1. MITRE ATT&CK에서 T1003.001을 직접 찾아보기**
- [attack.mitre.org](https://attack.mitre.org)에 들어가 T1003.001을 검색해 보세요.
- 이 기법은 공격자의 어떤 **목적(전술)**에 속하나요? '목적(전술)'과 '방법(기법)'은 어떻게 다를까요?
- 이 페이지에는 막는 방법과 알아채는 방법이 어떻게 적혀 있나요?

**질문 2. 보안 사고가 나면 어떤 순서로 대응할까?**
- 공개된 사고 대응 절차를 하나 찾아보세요. 보통 어떤 단계로 나뉘나요?
- PC를 네트워크에서 끊는 **격리**는 어느 단계에서, **누가 결정**하나요?
- 검색어: `NIST SP 800-61`, `incident response playbook`

**기록 담당에게 알려 줄 것:** 이 알림에 대응하려면 **어떤 문서의 어느 부분을 찾아봐야 하는지**
