9.29일 오전 네트워크 답안

제출자: 박혜윤
번호문제정답제출답정답여부해설
1Packet Tracer는 실제 네트워크 장비가 없어도 PC, 스위치, 라우터 등을 연결해 네트워크를 구성하고 동작을 살펴볼 수 있는 시뮬레이션 프로그램이다.OO정답다른 네트워크라면 원격 서버 MAC이 아니라 Default Gateway의 MAC 주소를 알아냅니다.
2L2 스위치는 일반적인 Ethernet Frame 전달 시 목적지 IP 주소를 보고 출력 Port를 결정한다.XX정답요청과 응답이 서로 다른 경로를 이용하는 비대칭 라우팅도 가능합니다.
3스위치는 들어온 Frame의 Source MAC Address를 이용해 MAC Address Table을 학습할 수 있다.OO정답L2 MAC 주소는 구간마다 바뀔 수 있지만, IP 목적지는 최종 서버를 향합니다.
4같은 VLAN과 같은 IP Subnet에 있는 두 PC가 통신할 때에도 반드시 Router를 거쳐야 한다.XX정답Routing 과정에서 기존 L2 Header는 제거되고 다음 링크에 맞는 Source/Destination MAC으로 다시 캡슐화됩니다.
5ARP는 IPv4 주소를 알고 있을 때 같은 LAN에서 해당 IP와 연결된 MAC 주소를 알아내는 데 사용될 수 있다.OO정답TTL 값을 단계적으로 증가시키며 중간 Router에서 발생하는 ICMP 응답을 이용합니다.
6목적지 MAC을 처음 알아내기 위해 보내는 일반적인 ARP Request의 Ethernet Destination MAC은 FF:FF:FF:FF:FF:FF이다.OO정답아직 Gateway MAC도 얻지 못했으므로 로컬 LAN, Gateway 주소, VLAN, 인터페이스 상태부터 확인하는 것이 자연스럽습니다.
7정상적인 IPv4 ping 통신에서는 ICMP Echo Request와 ICMP Echo Reply를 관찰할 수 있다.OO정답방화벽, ICMP 차단 정책, 중간 경로, 반환 경로 등 여러 원인이 있을 수 있습니다.
8Wireshark에서 icmp 표시 필터를 사용하면 ARP Frame도 함께 표시된다.XX정답RST가 돌아왔다는 것은 오히려 상대 Host까지 패킷이 도달했고 해당 Port가 닫혀 있거나 연결을 거부했을 가능성을 보여줍니다.
9Packet Tracer의 Simulation Mode에서는 PDU가 어느 장비를 거쳐 이동하는지 단계적으로 관찰할 수 있다.OO정답예상 경로와 실제 Simulation 흐름이 달라지는 지점이 장애 범위를 좁히는 중요한 단서입니다.
10Packet Tracer의 .pkt 파일과 Wireshark의 .pcapng 파일은 같은 종류의 패킷 캡처 파일이다.XX정답설계된 경로와 실제 관찰된 흐름의 차이를 이용해 장애 위치와 원인 후보를 좁힐 수 있습니다.
11PC가 같은 Subnet의 목적지 MAC을 모르는 상태에서 처음 ping하면 실제 링크로 ICMP Echo Request를 보내기 전에 ARP가 발생할 수 있다.OX오답Ethernet Frame 전송에는 목적지 MAC이 필요하므로 ARP Cache에 정보가 없다면 ARP가 먼저 발생할 수 있습니다.
12PC가 기본 경로를 이용해 다른 Subnet의 장비로 데이터를 보낼 때, 일반적으로 최종 목적지 PC의 MAC 주소를 ARP로 알아낸다.XO오답다른 Subnet이면 최종 목적지 MAC이 아니라 Default Gateway의 MAC을 알아냅니다.
13VLAN 10과 VLAN 20에 속한 PC가 같은 물리적 Switch에 연결되어 있으면 Router나 L3 Switch 없이 항상 서로 IP 통신할 수 있다.XX정답서로 다른 VLAN은 다른 Broadcast Domain이므로 VLAN 간 통신에는 L3 Routing이 필요합니다.
14Trunk Port의 중요한 목적 중 하나는 하나의 링크에서 여러 VLAN의 트래픽을 전달하는 것이다.OO정답하나의 Trunk Link에서 VLAN 10, VLAN 20 등 여러 VLAN의 Frame을 전달할 수 있습니다.
15VLAN 10에서 발생한 ARP Broadcast는 기본적으로 VLAN 20의 Access Port까지 전달된다.XX정답Broadcast는 같은 VLAN의 Broadcast Domain 안에서만 전달됩니다.
16L3 Switch의 SVI는 VLAN에 속한 PC들의 Default Gateway 역할을 할 수 있다.O잘모르겠음오답예를 들어 VLAN 10의 SVI를 192.168.10.1로 설정하면 VLAN 10 PC들의 Gateway로 사용할 수 있습니다.
17Router 또는 L3 Switch가 IP Routing을 수행할 때 Ethernet의 Source MAC과 Destination MAC은 다음 Ethernet 구간에 맞게 달라질 수 있다.O잘모르겠음오답L3 장비는 다음 Link로 전달할 때 새로운 Ethernet Frame을 구성합니다.
18일반적인 L2 Switch를 한 번 통과할 때마다 IP Packet의 TTL 값이 1씩 감소한다.XX정답TTL은 L3 Routing Hop에서 감소합니다. 일반적인 L2 Switching에서는 감소하지 않습니다.
19같은 Subnet에서 사용하지 않는 IP로 ping하면 ARP Request가 반복되고 ARP Reply가 나타나지 않을 수 있다.OO정답해당 IP를 가진 장비가 없다면 목적지 MAC을 알아낼 수 없어 ARP Request만 반복될 수 있습니다.
20Packet Tracer에서 만든 .pkt 파일을 Wireshark에서 일반 캡처 파일처럼 직접 열면 Simulation에서 발생한 모든 PDU를 그대로 분석할 수 있다.XX정답Packet Tracer Simulation과 Wireshark Capture는 서로 다른 방식입니다. .pkt를 .pcapng처럼 직접 분석할 수는 없습니다.
21내 PC가 기본 경로를 이용해 다른 네트워크의 원격 Linux 서버로 데이터를 보낼 때, 원격 서버의 MAC 주소를 직접 ARP로 알아낸다.XX정답원격 서버는 다른 네트워크에 있으므로 PC는 Default Gateway의 MAC 주소를 ARP로 알아냅니다.
22원격 Linux 서버로 가는 요청 Packet과 돌아오는 응답 Packet은 항상 동일한 Router 경로를 지나야 한다.XO오답요청과 응답이 서로 다른 경로를 사용하는 비대칭 라우팅도 가능합니다.
23NAT·터널링·특수한 주소 변경을 하지 않는 일반적인 Routing에서는 여러 Router를 지나더라도 Destination IP는 최종 원격 서버의 IP로 유지된다.O잘모르겠음오답L2 주소는 구간마다 바뀔 수 있지만 최종 Destination IP는 유지됩니다.
24Router가 Packet을 다음 Ethernet 네트워크로 전달할 때는 다음 Link에 맞는 새로운 Ethernet Frame으로 캡슐화해 전송한다.O잘모르겠음오답입력 Frame의 L2 정보를 처리한 후 다음 구간에 맞는 Source/Destination MAC으로 새 Frame을 구성합니다.
25tracert 또는 traceroute가 중간 Router를 찾아내는 데 이용하는 핵심 원리 중 하나는 IP의 TTL 값이다.O잘모르겠음오답TTL을 단계적으로 증가시키면서 각 Router의 ICMP Time Exceeded 응답을 이용해 Hop을 확인합니다.
26관련 인터페이스를 충분히 Capture했는데 Gateway IP에 대한 ARP Request만 반복되고 Reply가 없다면 원격 Linux 서버의 웹 서비스부터 확인하는 것이 가장 적절하다.XX정답아직 Gateway MAC도 얻지 못한 상태이므로 Local LAN, Gateway 주소, VLAN, Interface 상태부터 확인하는 것이 자연스럽습니다.
27원격 Linux 서버로 보낸 ICMP Echo Request는 보이는데 Echo Reply가 보이지 않으면 서버가 꺼져 있다고 단정할 수 있다.XX정답ICMP 차단, 방화벽, 중간 경로, 반환 경로, 캡처 위치 등 다양한 원인이 있을 수 있습니다.
28원격 Linux 서버의 TCP 서비스에 SYN을 보낸 뒤 SYN-ACK 대신 RST가 돌아왔다면 서버까지 IP 통신이 전혀 되지 않는 상태라고 결론 내릴 수 있다.X잘모르겠음오답RST가 돌아왔다는 것은 어떤 장비가 응답했다는 의미입니다. Port가 닫혀 있거나 연결을 거부했을 가능성을 생각할 수 있습니다.
29Packet Tracer에서 PC → L2 Switch → L3 Switch → L2 Switch → Server로 전달될 것으로 예상했는데 Simulation에서 L3 Switch 이후 전달이 확인되지 않는다면 Routing, SVI, VLAN 설정을 장애 후보로 살펴볼 수 있다.OO정답예상 경로와 실제 흐름이 달라지는 지점은 장애 범위를 좁히는 중요한 단서입니다.
30Python으로 네트워크 구성 정보를 분석해 예상 경로를 만들고, 대응 관계가 확인된 Packet Tracer Simulation 기록 또는 적절한 지점의 Wireshark 관찰과 비교하는 방식은 장애 분석에 활용할 수 있다.OO정답설계 기반 예상 경로와 실제 관찰 결과를 비교하면 흐름이 달라지는 지점과 원인 후보를 좁힐 수 있습니다.
