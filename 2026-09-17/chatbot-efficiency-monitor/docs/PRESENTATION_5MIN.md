# 5분 발표안

## 0:00~0:40 — 왜 만들었나
사내 챗봇을 도입하면 사용량은 쉽게 늘지만, 사용량만으로는 효율을 판단할 수 없습니다. 기존에 전산·인사·법률·회계 등 지원부서 직원에게 직접 들어오던 문의가 월평균 약 500건이었다가 챗봇 도입 후 월평균 3,000세션으로 늘더라도, 실제 해결률이 낮고 토큰 비용과 재질문이 증가하면 효율적이라고 볼 수 없습니다. 그래서 사람의 업무시간과 AI 비용을 같이 보는 프로젝트를 구성했습니다.

## 0:40~1:30 — 어떤 데이터를 보는가
도입 전에는 지원부서별 월 문의량과 사람이 문의 답변에 사용한 평균 처리시간을 봅니다. 이 시간은 담당자가 본래 업무에 사용하지 못한 시간으로 해석합니다. 도입 후에는 챗봇 세션, 해결률, 상담원 전환율, 해결시간, 대화 횟수, 토큰과 API 비용을 기록합니다. CPU와 메모리는 성과지표가 아니라 장애 분석용 보조지표로 사용합니다.

## 1:30~2:30 — 비용을 어떻게 줄였나
자주 쓰는 질문은 클릭 메뉴로 만들고, FAQ 키워드가 맞으면 LLM을 호출하지 않습니다. 보안과 권한 요청은 자동 처리하지 않고 담당자에게 넘기며, `심심해`, `놀자`, `뭐해`처럼 명백한 잡담성 질문만 API 호출 전에 차단합니다. 월급·구내식당·인터넷 장애처럼 업무 가능성이 있는 질문은 함부로 차단하지 않고 FAQ 또는 LLM 처리 대상으로 넘깁니다.

## 2:30~3:30 — 대시보드
대시보드에서는 도입 전 월평균 문의량과 도입 후 챗봇 세션을 비교하고, 해결률, 상담원 전환율, API 미사용 비율, 추정 인적시간 절감, 토큰/API 비용을 확인합니다. 부서와 월별 필터로 어떤 업무에서 효율이 낮은지도 확인할 수 있습니다.

## 3:30~4:20 — 시스템 엔지니어 관점
챗봇이 잘 답하는 것만으로는 운영이 끝나지 않습니다. API 지연, 장애, 토큰 급증, 로그 누락, DB 문제, 접근권한, 개인정보, 잘못된 FAQ 버전도 관리해야 합니다. 따라서 서비스 품질과 비용, 보안을 한 화면에서 확인하는 구조가 필요합니다.

## 4:20~5:00 — 결론
이 프로젝트의 핵심은 '챗봇을 얼마나 많이 사용했는가'가 아니라 '사람의 업무를 얼마나 안전하고 저렴하게 대체했는가'를 측정하는 것입니다. 이를 통해 챗봇이 실제로 회사에 도움이 되는지 수치로 판단할 수 있습니다.
