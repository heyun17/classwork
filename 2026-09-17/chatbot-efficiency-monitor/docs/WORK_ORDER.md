# 작업지시서

## 프로젝트명
사내 챗봇 비용·자원 절감 모니터링 및 분석 시스템

## 목적
사내 챗봇이 반복 문의를 자동화하여 절감한 인적 자원과, 이를 위해 소비한 토큰/API/인프라 비용을 같은 기준으로 비교한다. 사용량이 늘었지만 해결률이 낮거나 대화가 길어지는 경우를 비효율로 탐지한다.

## 대상 회사
가상회사 `GaonWorks Services`: 직원 620명, 서울 본사 및 2개 지사. 전산·인사·총무·재무/회계·보안 등 반복 문의가 발생하는 지원조직을 운영하며, 법률/컴플라이언스 문의도 챗봇 적용 후보로 가정한다.

## 핵심 요구사항
1. 도입 전 전산·인사·법률·회계 등 지원부서의 월평균 사람 문의량(테스트 기준 약 500건)과 평균 처리시간을 계산한다.
2. 도입 후 챗봇 세션, 해결률, 상담원 전환율, 평균 해결시간을 계산한다.
3. Input/Output token과 API 비용을 계산한다.
4. 챗봇이 대체한 추정 사람 처리시간과 금액을 계산한다.
5. FAQ/메뉴는 AI API를 사용하지 않는다.
6. 보안/권한 질문은 자동 처리하지 않고 담당자 절차로 전환한다.
7. 명백한 잡담성 질문과 과도한 대화/토큰 사용, API 오류·재시도를 이상치 후보로 기록한다.
8. 시스템 CPU/메모리/API 지연/오류는 장애 분석용 보조지표로 표시한다.
9. SQLite DB에서 모든 분석용 원천 데이터를 조회할 수 있어야 한다.
10. 직원이 챗봇을 사용할 때마다 사용 로그를 SQLite에 즉시 저장한다.
11. 저장된 실시간 로그는 설정 주기마다 집계하여 관리자 대시보드에 반영한다.
12. API 오류, Retry 증가, 토큰 과다, 직원별 이상 사용 후보가 감지되면 `alert_history`에 기록하고 선택적으로 Webhook/이메일로 알린다.
13. 개발 테스트 주기는 1분으로 사용하고, 발표/운영에서는 `monitoring/config.py`의 `MONITOR_INTERVAL_SECONDS`를 3600으로 변경할 수 있게 한다.
14. GitHub Actions로 최소 단위 테스트를 수행한다.

## 3인 분업

### 담당 A — 데이터/DB
- CSV 품질 확인
- SQLite 생성
- SQL 조회
- 데이터 정의서 관리
- 담당 브랜치: `feature/data-db`

### 담당 B — 분석/비용/이상치
- KPI 함수
- 비용/인적시간 계산
- 비효율 탐지
- 실시간 로그 주기 집계와 운영 이상치 규칙
- Webhook/이메일 알림 로직
- pytest
- 담당 브랜치: `feature/analysis`

### 담당 C — Streamlit/문서/발표
- 대시보드
- 필터와 시각화
- README/TASK/발표자료
- 담당 브랜치: `feature/dashboard-docs`

## 완료 기준
- `python scripts/build_db.py` 성공
- `pytest -q` 성공
- `streamlit run employee_chatbot.py` 실행 성공
- `streamlit run app.py` 실행 성공
- `python scripts/hourly_monitor.py` 실행 성공
- 직원 질문이 즉시 DB에 저장되고 설정 주기 후 대시보드에 반영
- KPI 수치가 DB 수동 조회 결과와 일치
- API 키/개인정보가 Git에 포함되지 않음
- 5분 이내 발표 가능
