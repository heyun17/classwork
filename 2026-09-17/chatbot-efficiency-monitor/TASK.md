# TASK.md

## 목표
사내 챗봇 도입이 사람의 업무시간을 실제로 줄이고 있는지, 그 절감 효과가 토큰/API/운영비보다 큰지를 대시보드에서 확인한다.

## 작업 순서

### 1단계 — 공통 정의 (3명 함께)
- KPI 정의: 문의 세션, 메시지 수, 해결률, 상담원 전환율, 해결시간, 토큰, API 비용, 인적시간.
- 개인정보/보안 원칙 합의.
- GitHub 저장소 생성 및 브랜치 규칙 합의.

### 2단계 — 1번 담당: 데이터/DB
- `data/*.csv` 검토 및 필요 시 테스트 데이터 수정.
- `scripts/build_db.py` 실행해 SQLite 생성.
- 테이블과 컬럼 정의 문서화.
- SQL 조회 검증.
- 직원 챗봇 사용 로그가 `live_chatbot_logs`에 즉시 저장되는지 확인.
- 주기 집계용 `hourly_snapshots`, `hourly_employee_snapshots`, `alert_history` 테이블 확인.
- 완료 조건: 기본 분석 테이블과 실시간 모니터링 테이블이 DB에 정상 생성되고 샘플 조회 성공.

### 3단계 — 2번 담당: 분석/비용
- `analysis/metrics.py` 지표 검증.
- 해결률/상담원 전환/평균시간/토큰/API비용 계산.
- 도입 전후 인적시간 비교.
- `analysis/anomaly.py` 비효율 후보 탐지.
- `monitoring/anomaly_rules.py`에서 API 오류, Retry, 토큰 과다, 직원별 이상 사용 후보 탐지.
- 완료 조건: 테스트 통과 및 수동 계산과 결과 일치.

### 4단계 — 3번 담당: 대시보드/문서
- `app.py` 실행.
- 월/부서 필터, KPI, 그래프, 이상치, 시스템 상태 화면 확인.
- `실시간 운영` 탭에서 주기 집계, 직원별 사용, 알림 이력 확인.
- README, 발표자료, Q&A 정리.
- 완료 조건: 새 PC에서 README 순서대로 실행 가능.

### 5단계 — 실시간 모니터링 통합
- `monitoring/config.py`에서 개발 테스트 주기 60초 확인.
- 직원 챗봇 질문 → 즉시 DB 저장 → `scripts/hourly_monitor.py` 집계 → 대시보드 반영 흐름 확인.
- `python scripts/simulate_live_usage.py --anomaly`로 이상치/알림 흐름 확인.
- 발표/운영 전에 필요하면 `MONITOR_INTERVAL_SECONDS = 3600`으로 변경.

### 6단계 — 최종 통합
- 세 브랜치를 PR로 main에 병합.
- GitHub Actions CI 통과 확인.
- 화면 수치가 DB/분석 결과와 같은지 교차 확인.
- 5분 발표 리허설.

## 절대 규칙
- 실제 사원 이름/개인정보/질문 원문을 테스트 데이터에 넣지 않는다.
- API 키는 `.env`에만 저장하고 Git에 올리지 않는다.
- 비용 단가는 코드에 여러 번 하드코딩하지 말고 설정 데이터에서 읽는다.
- 보안/권한 부여는 챗봇이 자동 실행하지 않는다.
- 챗봇 사용량만으로 성과를 판단하지 않는다.
